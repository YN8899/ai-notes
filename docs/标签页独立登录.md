# 标签页独立登录

同一浏览器可在标签页 A 登录管理员，在标签页 B 登录普通成员；两页的笔记、图片、后台任务和退出操作分别使用各自会话。

## 使用方式

1. 打开网站，登录账号 A。
2. 新开标签页访问相同网址，单独登录账号 B。
3. 刷新任意标签页保留该页登录。退出一页不会撤销另一页的会话，即使两页登录的是同一个账号。

新开、复制标签页和从地址栏重新导航会显示登录页。网页前进/后退重新载入文档也需要登录；当前应用内部切换“我的笔记”“模型设置”等不受影响。这样避免浏览器复制 sessionStorage 时意外共享会话，只有明确刷新恢复已有登录。

首次升级后需要重新登录一次，旧共享 Cookie 不会被新版网页自动继承。会话仍受原有效期限制；管理员停用用户或重置密码仍会撤销该用户的全部旧会话。

## 实现及边界

- 登录/注册/恢复使用 `/api/v1/auth/tab/*`，请求省略 Cookie；登录成功的凭证仅保存于当前页 sessionStorage。
- API 请求以 Authorization 携带本页凭证，修改操作携带同一会话的 X-CSRF-Token。无效显式凭证返回401，绝不退回共享 Cookie。
- 登录前采用 Origin + 必须的 X-Notes-Client 请求头验证，且不开放跨域 CORS，避免共享 CSRF Cookie 引起并发登录竞争。[OWASP 设计依据](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html#employing-custom-request-headers-for-ajaxapi)
- 私有图片以认证 fetch 读取为 Blob 后展示；凭证不放入 URL，上传使用相同会话。查询缓存仅在当前页清理，草稿按 owner 保存。
- 旧请求401、延迟退出响应仅可清理该请求对应凭证，不能清除随后建立的新登录。
- 原 Cookie API 保留兼容；数据库结构不变，无 migration（迁移）。

标签页隔离用于多账号使用，不是同源脚本之间的安全边界；sessionStorage 可被同源 JavaScript 读取。继续保留富文本安全处理，禁止把凭证写入日志、URL、localStorage 或广播。后续如增加第三方脚本或 CORS，需要重新审查认证边界。

## 发布与回退

本次实现仅在本地验收，尚未部署公网。上线需按既有 GitHub/ACR/Compose 流程更新前端及后端镜像，不能仅更新前端：旧后端没有 `/auth/tab/*` 路由。

发布前记录原 RELEASE_TAG 并按运维手册备份；获得部署授权后更新两端，验证两个标签页登录及退出、图片上传和阅读。没有数据库迁移；异常时恢复原前后端镜像标签并重新登录，保留数据库及图片卷，不使用 `down -v`。
