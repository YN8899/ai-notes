# M2 更新与数据恢复

本文件是发布前的检查和恢复方案，**不是已发布记录**。本轮 M2 开发未获得公网更新或 Git 提交/推送授权。

## 本地结构与兼容性

- 当前 M2 迁移头为 `84c6e9b302df`，49 张 public 表（含 `alembic_version`）。
- 新增链依次为卡片 `c4d72e9a1f03`、独立复习 `d58a3b7c901e`、测验 `e62a9c4f710b`、提醒 `f73b5d8a201c`、活动事件 `84c6e9b302df`。
- 所有迁移使用冻结 DDL。复习迁移会为已有已确认卡片回填独立手动计划及不可变历史；原笔记计划不受影响。
- 官方 FSRS、时区数据和完整依赖以锁文件为准。服务端按算法版本校验状态，不把未知版本静默转换为新状态。
- 整站备份保留旧 22/27/28/32 表档案，并增加 35/39/46/48/49 表精确结构档。备份必须选择与实际源结构相符的 revision，禁止靠伪改迁移标记通过检查。

## 发布前

1. 先读项目本地 `.local/ops/服务器连接与M1执行记录.md`、`公网当前运行与更新命令.md` 和 `监测运行与更新命令.md`，核对授权、当前镜像、完整 Compose 文件集合和原卷保护。
2. 核对本次代码、依赖锁、生成 API 契约、迁移与严格备份工具属于同一发布；独立运维快照不能仅靠更新应用镜像自动升级。
3. 预先验证目标备份工具支持当前公网旧结构及新 49 表结构。确认最新备份已在隔离环境真实恢复，保存镜像和卷身份。
4. 在独立空库演练从当前公网 revision 逐级升级，检查原数据投影、旧卡片回填、来源读取、账号 ZIP 和整站恢复。仅运行 `alembic check` 不能替代数据恢复演练。
5. 真实模型、外发资料、费用及公网维护仍需在相应授权范围内执行。本地合成接口通过不等于真实模型质量或真机验收通过。

## 正式更新窗口

1. 停止新写入，等待或安全终止运行中的处理、生成与评分；停止 Worker 和 API。记录明确的写入边界。
2. 用当前实际 revision 的严格配置进行一致性整站备份，保留原对象、数据库与恢复证据。
3. 沿用完整 HTTPS Compose 集合切换已核验的镜像，再执行数据库迁移。不要使用早期单独 HTTP Compose 命令替换当前配置。
4. 开放新写入前验证健康状态、账号边界、文件读取、卡片/测验/计划、站内提醒和统计；同时检查专用只读监测的连接、身份和快照兼容性。
5. 验证通过才恢复 API/Worker 并开放写入。观察错误、未知付费调用状态、定时汇总和备份日志，再记录最终运行身份。

## 回退原则

开放新写入前可以按已演练恢复点退回，并保留迁移后的卷供排查。开放新写入后不自动覆盖数据库；应停止相关功能、保留新数据并先制定对账方案。

不要在已有 M2 内容上直接执行降级到旧版本。降级会删除新卡片、测验、作答、计划和历史表；迁移的升降级测试仅可在可丢弃的隔离库执行。

## 账号 ZIP v3

v3 包含 32 类账号集合，其中新增 17 张学习表；保留 v1/v2 的离线恢复。用户创作的卡片、测验和历史不是可随意排除的缓存。

账号包不含登录凭据、API Key、租约和对象存储私有键。视觉来源携带受控哈希/尺寸、原文件 ID 与归档阅读路径；恢复时重建对象键，保留历史身份。操作请求编号和指纹用于恢复原始收据，不是认证令牌。

恢复工具只接受显式本地空库和独立空文件目录，保留原 UUID，设置新的账号密码，账号角色恢复为普通用户。不会恢复登录会话、模型配置或自动继续 AI 调用、转换和评分。提醒保留日期账本与历史数量，去除原 Job/outbox 关联，避免恢复历史多日提醒。

运行前查看工具的帮助及现有[账号归档恢复演练](账号归档恢复演练.md)。使用 `scripts/verify_export.py` 先离线检查，再用 `scripts/restore_export.py` 恢复；两者均应使用本发布版本，旧工具会拒绝未知 v3。

## 整站恢复

使用本发布的 `scripts/site_backup.py` 和匹配的精确结构档。恢复后先核对原始指纹与来源对象，再撤销旧会话、令牌及未完成任务；运行中 AI、卡片/测验生成及评分统一进入中断终态，保留已知用量，禁止自动付费重放。

不可变历史触发器的完整定义和启用状态也纳入验证；不允许通过停用触发器、宽泛允许 public 函数或扩展成员来绕过严格检查。具体恢复命令沿用[整站备份与隔离恢复](整站备份与隔离恢复.md)，执行后应追加当前实际结果，而非仅保留计划清单。
