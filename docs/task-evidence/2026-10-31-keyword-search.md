# 2026-10-31 T17 关键词搜索验证

日期/时区：2026-10-31，Asia/Shanghai。目标为总架构 6.4/T17 与[本轮设计](../superpowers/specs/2026-10-31-keyword-search-design.md)，对应[实施计划](../superpowers/plans/2026-10-31-keyword-search.md)。用户在 T16 完成后要求继续下一开发项，本轮未扩大到向量/分词服务、自动 OCR 或公网发布。

## 当前实现

- 当前账号未删除笔记的标题、标签、正文，以及最新有效成功 OCR 文档参与搜索；管理员不绕过所有者。
- 连续字串包含匹配，关键词去首尾空白后 1–100 Unicode code points；仅 ASCII 英文字母折叠大小写，百分号/下划线/反斜杠是普通字符。
- 笔记按标题/标签/正文优先合并一条字段匹配；OCR 按页面和实际矩形分组，先选择最新有效成功记录，再匹配文字。纠错稿含显式空稿优先，不返回同范围旧成功稿。
- 源所有者、回收站、页面/文件、SHA/尺寸、阅读图、源版本/页号/矩形、PDF 状态和 JSON 类型在数据库候选阶段核对，失效项不在分页后才被大量剔除。
- 类型、文件夹直属笔记本、笔记本和标签筛选与原列表一致；无权/不存在的组织筛选统一404。
- 结果键集游标绑定账号、查询和筛选，时间截止及 `(updated_at, kind, id)` 排序。列表为实时结果，不宣称跨页历史快照或大规模性能达标。
- 来源 GET 重新检查所有者、当前有效候选、版本及实际匹配内容的 match_hash；来源变化409、无权/回收404。match_hash 是内容比较值，不提供任何访问授权。
- 前端复用“我的笔记”筛选，正常列表输入关键词时切换搜索结果，回收站保留旧列表语义；文本高亮、只读来源、OCR 原图/区域和打开当前原笔记均已接入。

新增独立 `keyword_schemas/service/router` 和 `SearchResults`，没有增加表、列、任务或依赖，数据库仍是 `7c0a9d2e4f61` / 28 表；原 v1/v2 导出和整站备份格式不变。没有重构编辑器、上传或 T16 识别流程。

## 发现与修复

1. **相同几何区域被 JSON 数字写法分开**：最初按 JSON 文本分组会把0和0.0视为不同范围，旧稿可能继续命中。测试最初只作 Python 等值赋值，ORM 未实际更新，未形成复现条件；明确标记 JSON 字段修改后实际复现失败。修复使用原生 JSONB 数值等价分组，回归通过。
2. **标签改名不推进笔记版本**：已实际复现两例旧来源200而应409：改名后仍含关键词、以及标签不再匹配而静默切到正文。来源现在携带并校验实际匹配字段/完整文本/身份与版本的 match_hash，保留原权限与版本检查；两例回归和规格复审通过。
3. **PDF 显式 null kind 与旧缺失字段混淆**：将缺失 kind 兼容为 PDF 时，不能把显式 null 的损坏记录同样纳入候选。实际回归复现无效记录仍出现在结果，修复区分缺失字段与 JSON null，在分页前排除异常来源；正常旧 PDF 来源仍支持。

## 浏览器与可视证据

桌面1366×1000、手机尺寸390×844，8组交互通过：

- 普通来源 code point 高亮及滚动定位，用户 HTML 作为纯文本显示，无执行；搜索时不重复展示原 `/notes` 列表。
- 打开当前原笔记进入既有编辑器，不写入笔记。
- 搜索前后页、全部筛选保留、切换筛选重置游标与来源。
- OCR 原图实际矩形比例、原页/已复核状态、桌面/手机尺寸无横向溢出。
- 404/409 清除来源并明确重新搜索；空结果、网络错误重试、超长关键词不发请求。
- 迟到查询、迟到来源及旧401遇账号切换不回填私人内容、不使新账号失效；回收站仍请求旧 `/notes?q=`。

合成回执记录18次搜索 GET、5次来源 GET，来源请求均携带点击结果中的 match_hash；正常图片代理票据和登录/退出为模拟接口，搜索无模型/任务或笔记写入。截图及结果 JSON 位于忽略目录 `.local/qa-keyword-20261031/`；根任务已查看桌面文本来源和手机 OCR 来源截图，手机尺寸不当作真实手机验收。临时 Vite 由前端任务核为停止。
