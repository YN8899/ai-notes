# 笔记保存、冲突与恢复验收

执行日期：2026-10-16（Asia/Shanghai）。应用代码：`0833cc20a6f2566ccdfcad33101f914c254cdf2b`。

## 环境与范围

本机 Vite → FastAPI → PostgreSQL 开发库，图片使用本地存储，独立 Worker 运行。使用新建的合成文件夹、笔记本、标签、文字笔记，以及上一轮创建的两页合成图片笔记；未访问真实用户数据、OSS 或模型服务。

会话没有 Browser 插件，使用已有 Playwright 和 Edge 155.0.4283.45；本次视口为 1440×1100。本次是浏览器实际操作与接口结果对照，没有运行会清空业务表的 pytest，也没有修改业务代码。

## 实际结果：7 项通过

| 场景 | 操作与故障注入 | 核验结果 |
|---|---|---|
| 双窗口版本冲突 | 同一浏览器上下文的两个页面打开同一版本；窗口 A 保存后，窗口 B 提交旧版本修改 | B 收到 409，显示本机/服务器对比；服务器仍为 A 的内容，localStorage 保留 B 的草稿。用户明确选择服务器版本后，B 正确显示 A 的内容 |
| 慢保存期间继续编辑 | 将第一次 PATCH 的响应延迟 2.5 秒，在等待期间再次修改正文 | 两次 PATCH 串行执行，最终服务器正文是后一次输入，无需再编辑或手动保存 |
| 离线编辑与重连 | Playwright 模拟浏览器离线，编辑直至显示保存失败，再恢复联网 | 离线正文保留在本机草稿；重连后自动保存，服务器内容与离线输入一致 |
| 关闭页面后的草稿恢复 | 离线编辑并保存失败后关闭标签页；恢复联网，在同一浏览器上下文新建页面并重新打开笔记 | 页面提示恢复草稿，正文正确；带 revision 校验完成保存后，本机草稿被清理 |
| 历史版本 | 检查历史版本接口并在界面展开版本 1 | 原始正文、慢保存后的最终正文、关闭页面后恢复的正文均有对应快照；界面展示的版本 1 与初始正文一致 |
| 文字笔记回收站恢复 | 从界面删除并恢复包含笔记本、文件夹、标签及多次历史版本的测试笔记 | 正文、笔记本 ID、标签、笔记本所属文件夹均保留；界面选项一致，初始历史快照仍存在 |
| 图片笔记回收站恢复 | 保存两页页面/文件身份及顺序；删除笔记后读取旧图片凭证，再恢复笔记 | 删除期间图片访问返回 404；恢复后页面和文件 ID、文件名、顺序保持一致。重新获取凭证后阅读图可显示，阅读图 SHA-256 与删除前相同 |

本轮未发现需要修复的新业务缺陷。预期故障产生的 409、离线网络错误及删除期间图片 404 均单独识别；非预期 console error 和失败响应列表为空。页面没有框架错误遮罩，冲突对比与恢复后的图片截图已检查。

## 结论边界

- 关闭页面测试覆盖同一浏览器上下文的新标签页，不覆盖清除站点数据、更换浏览器配置或整机断电。
- 离线通过浏览器网络模拟，慢保存通过拦截并延迟响应；不代表全部真实网络故障。
- 历史版本测试覆盖记录和查看，不声明实现了将任意历史版本恢复为当前版本的额外功能。
- 本轮不覆盖图片处理崩溃后的孤儿对象清理、容量回收、真实手机触控、真实 OSS、跨账号全量回归、云端重启或备份恢复。
- 这些场景通过后，M1 的其余验收项仍须按实际范围分别推进。
