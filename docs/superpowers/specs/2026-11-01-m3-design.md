# M3 好友、私聊、社区与工作台设计

日期：2026-11-01。承接总架构 T25–T29；用户明确要求持续开发整个 M3，完成后报告。此授权覆盖本地实现、设计选择、隔离测试和文档；不包含 commit/push、公网迁移、外部消息或付费调用。保持 main，保留原有 dirty/untracked。用户连续执行要求优先于技能中的逐节审批/提交步骤。

## 范围与方案

沿用 React/FastAPI 模块化单体、PostgreSQL、Storage adapter、独立 Worker。新增 social、community 模块，不引入消息中间件。相比预先引入 Redis/独立聊天服务，此方案复用当前事务、会话和部署；相比只做前端静态社交页，它提供真实持久化、权限与恢复。实时只用于通知，数据库始终是消息事实来源；单 API 进程是首版部署边界。

### T25 关系、资料、分享

登录成员按用户名搜索成员；返回基础身份，不暴露邮箱、学习统计或笔记。好友申请具有发送者、接收者和待处理/接受/拒绝状态；禁止自加、重复申请，只有接收者可接受/拒绝。好友关系和单向关注独立；解除好友终结双方关系并停止已有分享的新读取。资料含简介、学科和详情，基础显示名可见，详细资料默认为好友可见，用户可设仅自己。更改显示名复用 users。

笔记所有者向当前好友授予只读权限；专用分享列表、正文、页面和图片接口每次重验双方账号、好友关系、授权与笔记未删除。撤销立即阻断新的正文和文件请求。不改现有 notes/files 的 owner-only 入口；分享不授予 AI、导出、复制、修改和访问笔记历史/私人AI或学习信息的能力。前端独立只读阅读器，显示分享者及当前版本。

### T26 私聊与实时

一个好友对一个持久线程，规范双方顺序并唯一约束。消息具有 sender_id + client_message_id 幂等键及线程单调 seq；正文/附件冻结，重放相同请求返回原回执，异内容复用键返回409。只允许好友发送；解除好友保留参与者的历史阅读与附件，不允许新发送。非参与者和管理员不能读取消息与附件。游标补拉使用 after_seq，已读游标只能单调前进且不能超过线程已存在序号。

附件有独立受限上传与归属，不允许任意引用别人的 file_id；检查大小、类型和内容，以服务端生成键保存，下载再次验证参与者。WebSocket 使用同源握手、短期一次性票据（HTTP认证+CSRF签发，不把长期会话放URL），每次推送重验有效会话；广播仅事件ID/线程ID，不广播正文。重连/漏事件依靠HTTP补拉，不把在线当已读。

### T27 社区副本

首版社区对登录且active成员可见。用户可编辑原创帖子，或从自己笔记准备发布副本；保存来源版本、正文、原图/阅读图的独立副本。不提供通向私人接口的链接。源修改、删除、分享撤销不影响已发布副本。图片复制经持久jobs/租约处理，全部复制并校验成功后才允许发布；失败保持非公开并支持重试。发布/更新/撤回使用revision保护，已发布内容更新需显式重新发布；撤回立即停止展示和新文件读取。

### T28 互动与审核

帖子含学科、类型、自由标签；稳定游标信息流支持最新、关注、规则推荐（按冻结的内容完整度分数与发布时间解释，真实互动计数单独展示，支持切换）、学科/类型/标签筛选。仅published且作者active的内容进入信息流。评论、点赞、收藏、举报均持久化和幂等；评论作者可删除自己的评论。管理员只管理公开社区及举报，审核动作审计，可下架/恢复，处理后记录理由；不扩大私人资源读取权限。下架/撤回的帖子及附件不能通过收藏/评论/直链继续访问。

### T29 工作台与设置

现有首页整合笔记、AI、到期复习、未读私聊、好友分享和社区入口，支持桌面/390px；新增好友、消息、社区、个人设置导航。个人设置包括基础资料/隐私，继续保留现有学习偏好。缓存以账号隔离，切换/退出终止实时连接和在途请求，禁止其他账号残留。所有按钮连接真实API，提供加载、空态、失败、冲突和分页。

## 数据与工程闭环

迁移采用冻结DDL，所有新表显式UUID/FK/约束/索引；不迁移 notes_dev/公网。新增数据加入账号归档新版本、离线验证和空库恢复，兼容v1–v3。跨账号关系/消息恢复不能赋予对其他现存用户的访问：个人归档保留自己的社交记录为离线历史，不自动重建外部成员/授权或发送任务；必要外部显示身份脱敏且明示。整站备份完整保留新表/附件与精确schema profile，恢复终态化未完成发布任务，撤销旧会话和实时票据，不自动重放外部调用。文件引用清理不得清除有效聊天附件或社区副本。

同步OpenAPI/TypeScript契约，增加权限/重复/并发/撤销/离线/恢复测试；真实PG隔离测试、前端类型与构建、前端Node测试、工具回归、桌面与移动浏览器真实App流程、独立规格和质量审查均为完成门槛。测试不使用真实凭据、OSS、模型或生产数据；用户真机/线上部署单独安排。

## 实施取舍补充

规则推荐采用冻结内容完整度（独立图片、正文长度）与发布时间，不用会随分页变化的实时点赞数排序，避免活跃互动导致游标漏项/重复；界面解释每帖规则且可切回最新/关注。社区快照保留只用于历史溯源的source_note_id/source_revision；同一来源版本的编辑和重新发布从上个独立社区副本复制，不依赖私人来源继续存在。只有显式选择新来源/版本才重新校验私人笔记和转换进度。
