# T17 中文关键词搜索设计

日期：2026-10-31，Asia/Shanghai。承接总架构 6.4、T17 与 M2 开发计划；用户在 T16 完成后明确要求“继续下一步开发”，本轮沿用已确定的中文包含匹配、权限、分页和来源定位范围。保留现有未提交内容，只在本地开发验证，无提交、付费调用或公网发布。

## 1. 方案与范围

沿用计划中的 PostgreSQL 实时中文包含匹配。相比英文全文检索配置，此方式能直接处理中文连续子串；相比现在引入分词/向量服务，不增加数据库结构、索引任务、模型配置或迁移。数据规模增大后再测量并改进索引，不将首版描述为大规模搜索方案。

首版搜索当前账号未删除笔记的标题、标签、富文本派生 plain_text，以及当前有效 OCR 文档。查询为去除首尾空白后的连续字串，1–100 字符；`%`、`_`、反斜杠按普通字符处理，不是通配符。ASCII 英文字母不区分大小写，其他字符按原样匹配；不做模糊纠错、中文分词、语义或图片内容猜测。搜索不触发识别、模型请求或文件写入。

保留现有类型、文件夹直属笔记本、笔记本与标签筛选。回收站仍是明确的独立列表，不进入全库搜索结果。无 OCR 的笔记仍能按标题/标签/正文搜索。

## 2. 搜索候选与版本

- 同一篇笔记的标题/标签/正文合为一个 note 结果，匹配优先级为标题、标签、正文，显示实际匹配字段和摘要。
- OCR 按当前页面与提交时矩形分组（整页为独立范围），取最新成功且来源有效的识别尝试；新失败或进行中尝试不替代之前成功文本。不同范围可各有结果，旧成功稿不在同范围新成功稿后继续参与匹配。
- OCR 有人工纠错稿时只搜纠错稿，包括显式保存的空稿；否则搜成功运行原文。显示已复核/未复核。
- 所有者、未删除状态、页面/文件 ID、文件 ready/摘要/尺寸、冻结阅读图/字节、来源笔记与页号/区域均需有效。源码读取与调用用量不进入搜索内容。
- 不能先按关键词挑中旧 OCR 后再取最新，也不能分页后才大量过滤失效候选，导致空页或漏页。使用数据库候选与窗口函数在关键词匹配前选择最新有效成功稿。

## 3. 接口与分页

`GET /api/v1/search`：参数 q、limit（默认20，上限50）、cursor、可选 kind/notebook_id/folder_id/tag_id。返回 items、next_cursor、limit。

结果包含 id（笔记或 OCR ID）、kind（note/ocr）、note_id、title、note_kind、matched_field、snippet、snippet 内的 match_start/match_end（Unicode code point）、source_revision、match_hash、可选 ocr_revision/page_id/page_number/region/reviewed、updated_at。match_hash 是实际匹配字段/完整文本及来源身份/版本的内容摘要，用于检测标签改名等不增加笔记版本的变化，不是授权凭据。结果不含对象键、原始模型请求、用户凭据或其他账号总数。摘要最多约 180 字符（另有省略号），纯文本显示匹配高亮。

按内容更新时间、结果类型、ID 降序键集分页。游标绑定账号、关键词及所有筛选，严格校验格式/时间/类型；第一页时间截止限制后续插入/修改。列表是实时可访问结果，不是历史快照：并发删除/修改可能使后续项消失，刷新重新搜索即可；不保留长数据库事务。

`GET /api/v1/search/{kind}/{id}/source`：参数 q、source_revision、点击结果中的 match_hash 与 OCR 时所需 ocr_revision。重新选择当前有效候选并核验匹配、内容摘要和版本；不可访问返回404，内容/纠错/最新尝试变化返回409，提示重新搜索。不能把搜索摘要当作之后的访问授权。

来源响应包含经过核验的笔记标题/ID、字段、当前匹配文本与高亮起止、版本；OCR 另含文件ID、页面ID/页号/区域、识别文档ID及复核标记。普通正文以只读原文显示并定位匹配处；OCR 显示识别文字匹配并用现有 ImageReader 定位原页/区域。另提供打开当前原笔记的操作，不直接修改编辑器或覆盖草稿。

## 4. 前端

升级“我的笔记”搜索为上述范围，保持已有筛选与分页体验。搜索时显示结果类型/匹配字段/摘要/复核状态，点击“查看匹配来源”按实时来源接口展开只读阅读；可再打开原笔记。回收站保留原列表筛选语义。

关键词或筛选变化重置游标与来源，上一页/下一页不混用旧参数；会话或账号切换后丢弃迟到响应及私人界面。匹配高亮以文本片段与 `<mark>` 表达，不能插入用户 HTML。明确错误、无结果、来源变化、加载与重试状态。搜索输入不产生模型费用；无新自动上传/识别行为。

## 5. 实现边界

新增独立 keyword_service、keyword_schemas、keyword_router，注册到现有应用，OCR 模块保持原行为。新增前端 SearchResults 与来源阅读组件，轻量接入 NotesWorkspace，复用 ImageReader；不重构编辑器或图片上传。

不新增表/列/迁移，T16 `7c0a9d2e4f61` 及既有导出/备份格式保持。本轮更新 OpenAPI/TypeScript、使用说明与 M2 状态。SQL 参数绑定，限定范围/分页，避免逐页加载全部私有文件；来源阅读不请求存储对象直到有权限的现有图片代理收到明确阅读操作。
