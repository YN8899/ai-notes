# T16 首个 OCR 闭环设计草案

日期：2026-10-31，Asia/Shanghai。状态：用户已回复“你开始开发吧”，按路径 A 开始本地开发。承接 [M2 开发计划](../../M2开发计划.md)；本方案不包含付费模型测试或公网部署授权。

## 1. 目标与路径选择

用户打开自己的图片笔记或已转换的 PDF 页面，显式发起当前一页或一个矩形选区的文字识别；后台完成后可阅读、纠错、保存，并定位回同一原页/区域。识别失败不影响原图阅读，也不覆盖笔记正文。

| 路径 | 取舍 |
|---|---|
| A：手动单页/选区，复用现有视觉模型适配（推荐） | 延续现有权限、阅读图、选区和调用用量记录；每次可明确看到发送范围，首个闭环小且可验证。模型结果需要人工核对，不承诺逐字准确。 |
| B：上传后自动识别全部页面 | 使用方便，但默认外发材料和批量调用扩大范围；需先确定用户开关、批次预算、并发和中断策略。留作后续。 |
| C：接入专用 OCR 引擎或新服务 | 可以针对版面定位评估，但增加依赖/服务、资源或凭据管理；当前未选择具体产品，不预先引入。 |

本草案选择 A。项目代码中的能力表将现有 DeepSeek Flash 标为支持图片，本设计复用该适配边界；这不是对服务商最新能力、价格或识别准确率的重新核验。进入真实模型验收前另行核验。

## 2. 首版范围

- 支持普通图片笔记页面和已成功转换的单个 PDF 页，整页或单个已有矩形选区。
- 一次显式提交计划最多一次模型请求，不自动拆页/扩展区域，不自动重发失败的付费请求。
- 输出为文字与可阅读的公式 LaTeX，始终提示识别结果需核对；不声称具备可靠的概率置信度、逐字坐标或复杂版面还原。
- 定位范围来自用户提交且经服务器校验的矩形；整页识别定位至整页，不伪造模型返回的行级坐标。
- 用户可编辑纠错文本；模型识别原文与纠错稿分离。重新识别生成新尝试，不静默覆盖已保存纠错稿。
- 首版不实现全库搜索、向量、卡片、自动整本 OCR 或将识别结果自动写入原图片笔记正文。

## 3. 现有结构与模块边界

代码盘点确认：

- `backend/app/modules/files/models.py` 的 `NotePage` 保存页面 ID、文件 ID、页序和 revision；普通图片和 PDF 转换页复用该表。
- `backend/app/modules/ai/image_context.py` 已有校验/有界读取/实际裁图，`pdf_context.py` 处理 PDF 来源；不允许客户端指定私有对象键或外部图片 URL。
- `backend/app/modules/ai/models.py`、`chat_service.py`、`chat_provider.py` 已有持久化运行、受控适配、用量、明确终态和禁止自动重发 POST 的边界；`worker.py` 已轮询 AI 任务。
- `frontend/src/features/ai/RegionSelection.tsx` 与 `image-region.ts` 已有归一化选区，`ImageReader.tsx` 能定位已知区域。
- 当前 `jobs` 默认重试机制不适合直接包装可能收费的模型 POST；OCR 执行不另建一个会重复发起同一模型请求的普通 Job。

新增 `backend/app/modules/search/` 下的 OCR 模型、接口和业务服务，承担识别文档、纠错和来源有效性；首版还不提供搜索接口。模型执行优先复用已有 `AiRun`、Worker 和单次适配，不建立第二套凭据、任务租约或用量账本。OCR 内部使用独立对话/运行，标识用途，在普通聊天列表中不混入系统识别任务，不能破坏现有聊天请求哈希及历史来源规则。

前端新增独立 OCR 面板，通过图片和 PDF 页面入口复用；沿用已有样式和会话切换时的迟到响应屏障，不重构大体积页面组件。

## 4. 数据与版本

拟增加 `ocr_documents` 表，每次识别尝试一条记录，包含所有者、笔记/页面/文件身份、来源快照、关联运行、纠错文本、独立纠错 revision、复核标记和时间。模型/已知用量及识别原文从关联运行读取，不重复计入用量。

来源快照记录提交时 note/page revision、原文件 ID/摘要、页面尺寸、PDF 原页号（如有）与归一化选区。页码用于展示，页面 ID 与文件身份用于定位；不能仅按列表中的“第几页”重新寻找资料。

读取、调用前和写回/发布结果前均核对当前权限、非回收站状态和来源身份。换图或页面移除后，旧结果不能作为当前页识别文本；保留记录并明确失效。单纯改标题或调页序，在页面及文件内容身份未变时不让结果指向另一页，也不无故丢弃纠错。新来源内容要发起新尝试。

纠错保存携带 OCR 自身 revision，过期更新返回 409，保留客户端草稿；识别结果不能反向覆盖纠错文本。后续 T17 仅索引可访问且来源仍有效的文档，优先使用已保存纠错文本，并区分未复核状态。

数据库采用 Alembic 增量迁移，不改已有笔记正文或历史。关联的所有者约束、唯一请求键与外键按当前项目约定校验；旧数据不自动触发识别。

## 5. 接口与操作流程

拟提供以下接口，路径为设计提案，实施时同步 OpenAPI 与 TypeScript 生成类型：

- `POST /api/v1/ocr/documents`：提交笔记、页面、可选选区与请求键；服务器核验共享模型、限额和来源，再在同一事务创建文档和关联运行。重复相同请求返回原记录，改变参数不能复用请求键。
- `GET /api/v1/ocr/documents`：按本人笔记/页面分页列出识别尝试与状态，避免无限返回。
- `GET /api/v1/ocr/documents/{id}`：返回状态、原识别文本、纠错稿、来源与失效原因；不能返回其他用户数据或私有对象键。
- `PATCH /api/v1/ocr/documents/{id}`：基于 revision 保存纠错稿及复核标记，冲突保留草稿。
- 失败后的“重新识别”创建新的显式提交/请求键。超时或进程中断后调用是否已被收费可能未知，不后台补发；页面清楚提示这是新的模型调用。

复用当前每用户活动运行与频率约束，OCR 和聊天共享限制，避免另开入口绕过限额。模型未配置时显示不可用，普通阅读和编辑继续可用。

UI 依次展示选择范围、发送确认、排队/识别/失败或完成、原文与纠错、保存状态和返回原页。不能因前端轮询、刷新、切换账号或重新进入页面再次发起识别。已被回收或越权的来源按现有权限约定拒绝，管理员也不例外。

## 6. 导出、恢复与运维兼容

新增持久化内容必须进入当前账号归档、离线校验与空环境恢复，包含来源身份、关联运行和纠错稿，且不得导出凭据、内部请求消息或实际对象键。为新增归档内容明确格式版本与旧包兼容规则，不静默改变旧格式。

整站备份/恢复的精确 schema、表集合及关系核验需识别新迁移，同时保留 c39/27 表恢复点的显式兼容路径；新结构不能误通过旧结构校验。源文件仍由已有页面/文件引用保留，不以 OCR 替代历史文件保护。普通图片/PDF/聊天/导出原有回归必须继续通过。

当前公网独立运维工具快照不会随代码自动更新。真正发布新 schema 前，另按项目私密运维指南准备监测、日备/恢复工具的兼容更新、备份、迁移和发布方案；不能直接执行旧精确守卫。此处是新功能发布前提，不恢复执行已延期的长期周期验收。

## 7. 验证与交付边界

初期仅本地隔离开发，使用合成图片/PDF 与模拟模型，不调用付费 API、不外发真实材料。主要验证：

1. 正常单页/选区，普通图片与 PDF 页分别能显示文字、保存纠错、定位原页；不改原图和原正文。
2. 同请求去重、并发提交及活动运行限制；轮询和刷新不新增请求。
3. 超时、错误输出、截断、租约失效和 Worker 重启不悄悄重发模型请求；未完成文本不能冒充成功识别。
4. 识别期间换图/删页/回收、运行终态前权限变化；旧来源不发布为新页结果。
5. 纠错冲突、重新识别后旧稿保持、排序与改标题后定位正确。
6. 普通用户和管理员跨账号读取/编辑/识别/定位/导出拒绝；会话切换清除私人面板和待处理响应。
7. 新旧导出格式校验/隔离恢复、增量迁移与备份 schema 兼容，以及现有相关回归、类型和构建。

本地验证通过后再单独决定真实模型材料、预算和测试次数，以及是否安排公网发布。此前 M1 的照片授权和费用账本不自动延伸至本任务。
