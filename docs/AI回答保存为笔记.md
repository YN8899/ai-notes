# AI 回答保存为笔记

2026-10-20：在已有文字与 PDF 对话上增加“保存为笔记”。本阶段已完成本机迁移、自动回归与网页实测，结果见 [阶段证据](task-evidence/2026-10-20-save-ai-answer.md)，不以代码实现代替验收，也不代表完整 M1 或云端部署已完成。

## 使用方式

1. 在“AI 对话”中等待一轮回答完整生成。只有成功完成且正文非空的回答可以保存；排队、生成中、取消、中断、失败或截断的回答不能保存。
2. 点击该回答下的“保存为笔记”，确认标题，选择目标笔记本；也可保存为未分类笔记。
3. 确认后生成一篇普通文字笔记，可点击“打开笔记”继续编辑。正文保留本轮问题、回答和生成模型；附有 PDF 时，还保留 PDF 名称、当时的来源版本、所选原页码与回答引用的合法页码。
4. 在笔记的独立来源区域打开引用原页，也可展开本次来源的全部原页。来源阅读器支持返回笔记。

保存直接使用服务端已经持久化的回答，不重新生成、不再调用模型，也不要求用户配置个人 Key。浏览器只提交标题和笔记本 ID，不能借此替换服务端的问题、回答或来源。

## 编辑、重复保存与回收站

首次保存会在同一数据库事务中创建文字笔记、初始历史版本与回答来源关联。每个用户的同一轮回答最多关联一篇保存笔记；并发点击、网络响应丢失后的重试和再次保存均返回已有笔记，不生成副本。

之后可以在笔记中修改标题、正文与所属笔记本。再次保存这轮回答会返回现有笔记的当前信息，不覆盖这些编辑。若笔记已移入回收站，再次保存仍指向该笔记，不自动恢复或重建；需要从回收站恢复后继续使用。

来源信息独立于可编辑正文保留。删除或改写正文中的“PDF 来源”文字，不会改变独立来源区域记录的原始 PDF 名称、版本和原页引用。模型输出中的有效 `[[p:N]]` 标记在保存正文中变为可读的原 PDF 页码文字，实际原页入口由来源区域提供；未在本轮所选范围内的标记保持普通文字。

## 来源权限与失效

回答、保存笔记与来源读取均按私人所有者检查，管理员也不能绕过其他成员的权限。公开来源快照只包含笔记 ID、标题、版本、选择模式、page_id 和原页码，不包含私有对象键或文件存储元数据。

原 PDF 删除后，已经完成的回答仍可保存，保存笔记中的文字与来源快照继续保留。打开原页仍须通过现有来源校验：来源已删除或页图身份失效时显示不可用，不因保存回答而复制、恢复或公开原 PDF。来源笔记版本发生变化时，阅读器会提示引用来自历史版本。

## 正文格式边界

回答以普通文字构造 Tiptap 段落，问题、回答、模型与 PDF 来源使用分节标题。模型返回的 HTML、Markdown 链接、代码围栏与公式语法都作为文字保留，不自动执行或转换。

本阶段没有新增 AI 回答的 Markdown、公式自动排版，也没有实现矩形选区或富文本选段来源引用。保存正文仍受现有笔记的大小与结构限制，超过限制时会提示无法保存。

## 接口与迁移

| 接口 | 用途 |
|---|---|
| GET `/api/v1/ai/conversations/{conversation_id}/saved-notes` | 查询本人对话内各轮回答的保存状态与对应笔记当前信息，包含回收站状态 |
| POST `/api/v1/ai/runs/{run_id}/save-note` | 提交 `title`、可选 `notebook_id`，保存成功回答或返回已有保存结果 |
| GET `/api/v1/notes/{note_id}/ai-answer` | 查询本人未删除笔记的独立回答来源；普通笔记返回 `null` |

原页继续通过 GET `/api/v1/ai/runs/{run_id}/source-pages/{page_id}` 读取授权后的页面信息。写请求沿用 CSRF、Origin 与账户状态校验。

迁移 `2ef16e7ca892` 接在 `63b9d8343e02` 之后，为 `ai_runs` 增加所有者与运行 ID 的联合唯一约束，并创建 `ai_saved_notes`。关联表以组合外键约束运行和笔记归属，以唯一约束保证一轮回答只保存一次、一篇笔记只关联一轮回答，同时保留安全来源快照与引用页码。部署前应备份应用数据库，再执行 `alembic upgrade head`；当前实际执行结果见阶段证据。
