# AI 回答保存为笔记

2026-10-20：在已有文字与 PDF 对话上增加“保存为笔记”，随后接入 Markdown 和数学公式排版。保存基础阶段的迁移与验收见 [阶段证据](task-evidence/2026-10-20-save-ai-answer.md)。当前仍是本机功能，不代表完整 M1 或云端部署已完成。

## 使用方式

1. 在“AI 对话”中等待一轮回答完整生成。只有成功完成且正文非空的回答可以保存；排队、生成中、取消、中断、失败或截断的回答不能保存。
2. 点击该回答下的“保存为笔记”，确认标题，选择目标笔记本；也可保存为未分类笔记。
3. 确认后生成一篇普通文字笔记，可点击“打开笔记”继续编辑。正文保留本轮问题、回答和生成模型；附有 PDF 时，还保留 PDF 名称、当时的来源版本、所选原页码与回答引用的合法页码。
4. 在笔记的独立来源区域打开引用原页，也可展开本次来源的全部原页。来源阅读器支持返回笔记。

保存直接使用服务端已经持久化的回答，不重新生成、不再调用模型，也不要求用户配置个人 Key。浏览器只提交标题和笔记本 ID，不能借此替换服务端的问题、回答或来源。

## 编辑、重复保存与回收站

首次保存会在同一数据库事务中创建文字笔记、初始历史版本与回答来源关联。每个用户的同一轮回答最多关联一篇保存笔记；并发点击、网络响应丢失后的重试和再次保存均返回已有笔记，不生成副本。

之后可以在笔记中修改标题、正文与所属笔记本。再次保存这轮回答会返回现有笔记的当前信息，不覆盖这些编辑。若笔记已移入回收站，再次保存仍指向该笔记，不自动恢复或重建；需要从回收站恢复后继续使用。

来源信息独立于可编辑正文保留。删除或改写正文中的“PDF 来源”文字，不会改变独立来源区域记录的原始 PDF 名称、版本和原页引用。普通正文中的有效 `[[p:N]]` 标记在保存后变为可读页码，实际原页入口由来源区域提供；代码、公式、链接标签和未选页标记均保持字面内容。

## 来源权限与失效

回答、保存笔记与来源读取均按私人所有者检查，管理员也不能绕过其他成员的权限。公开来源快照只包含笔记 ID、标题、版本、选择模式、page_id 和原页码，不包含私有对象键或文件存储元数据。

原 PDF 删除后，已经完成的回答仍可保存，保存笔记中的文字与来源快照继续保留。打开原页仍须通过现有来源校验：来源已删除或页图身份失效时显示不可用，不因保存回答而复制、恢复或公开原 PDF。来源笔记版本发生变化时，阅读器会提示引用来自历史版本。

## Markdown 与数学公式

聊天生成过程中显示原文，结束后由服务端统一解析为受控 Tiptap JSON，聊天和新保存笔记共用解析规则。支持一至六级标题、粗体、斜体、删除线、有序/无序列表、引用、行内代码、代码块、分隔线和显式 HTTP(S) 链接。有序列表保留起始序号，代码中的公式与引用标记不被解释。

公式支持 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]`。行内/独立公式保存为编辑器的 `inlineMath`/`blockMath` 节点，保留 LaTeX；显示使用现有 KaTeX，宽公式和代码局部滚动。无效公式显示原 LaTeX 和提示，不影响其余回答。JSON 导出保留结构，Markdown 导出保留公式与代码内容，特殊格式转换仍可能有损。

HTML 标签按文字显示；外部图片只保留说明，不自动请求图片地址。链接仅允许 HTTP(S)；KaTeX 禁用受信任扩展并限制展开次数与尺寸。单公式超过 8 KiB 时按原文保留；全文的解析输入/输出预算为 250000 字节，另有 8000 个解析标记/分隔符与 16 层嵌套限制（此处不是服务商计费 token），超限时整条回答回退原文，不截断原回答。回退时不猜测代码中的引用，仍可从来源区域打开全部原页。

旧聊天读取时也应用排版；已保存笔记保留当前正文和编辑记录，不自动重写。保存正文仍受现有笔记的大小与结构限制，超过限制时提示无法保存。表格、远程图片嵌入、矩形选区和富文本选段来源尚未加入。

实现参考：[MarkdownIt 安全配置](https://markdown-it-py.readthedocs.io/en/latest/security.html)、[数学解析插件](https://mdit-py-plugins.readthedocs.io/en/latest/#math)、[KaTeX 安全配置](https://katex.org/docs/security.html)。

## 接口与迁移

| 接口 | 用途 |
|---|---|
| GET `/api/v1/ai/conversations/{conversation_id}/saved-notes` | 查询本人对话内各轮回答的保存状态与对应笔记当前信息，包含回收站状态 |
| POST `/api/v1/ai/runs/{run_id}/save-note` | 提交 `title`、可选 `notebook_id`，保存成功回答或返回已有保存结果 |
| GET `/api/v1/notes/{note_id}/ai-answer` | 查询本人未删除笔记的独立回答来源；普通笔记返回 `null` |

原页继续通过 GET `/api/v1/ai/runs/{run_id}/source-pages/{page_id}` 读取授权后的页面信息。写请求沿用 CSRF、Origin 与账户状态校验。

排版阶段无需新增数据库迁移。`RunOut` 新增只读 `formatted_answer`：生成中为空，终态返回 `body_json` 与 `fallback`；原始 `answer` 不变，SSE 的 `done` 携带格式树，delta/state 不重复发送格式内容。浏览器对每个 SSE 事件及未完成残留单独执行长度限制，合法事件合并在同一网络块时不会误报。

迁移 `2ef16e7ca892` 接在 `63b9d8343e02` 之后，为 `ai_runs` 增加所有者与运行 ID 的联合唯一约束，并创建 `ai_saved_notes`。关联表以组合外键约束运行和笔记归属，以唯一约束保证一轮回答只保存一次、一篇笔记只关联一轮回答，同时保留安全来源快照与引用页码。部署前应备份应用数据库，再执行 `alembic upgrade head`；当前实际执行结果见阶段证据。
